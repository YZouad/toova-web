## Identity Management

No `identify()`-equivalent call exists. `gtag('config', GA_ID, {...})` is called once at boot with no user ID or traits. Every event above is anonymous/session-scoped — none of them can be tied to a specific Supabase auth user id, and there's no signal distinguishing a guest session from a signed-in one.

No `group()` calls — expected, since the product model records this as a B2C product with no account/organization hierarchy.

## Observed Patterns

- **Naming:** event names (the strings sent to GA4) are consistently `snake_case`; wrapper function names are consistently `camelCase`. No mixing observed.
- **Centralization:** every call funnels through one internal `trackEvent()` in `src/lib/analytics.ts`. No direct `window.gtag()` or `window.dataLayer` calls exist anywhere outside that file — 9 files call into it via 7 named wrapper functions.
- **`create_room` fires empty:** `trackCreateRoom()` is called with zero arguments at its one call site (`useRoomLayout.ts:363`), even though the function accepts optional `template_id`/`guest_restore`. Neither property has ever been observed being set.
- **Guest-only sessions are invisible:** a user who starts designing as a guest and never signs up never triggers `createRoomWithGeometry` (that function is only reached for authenticated room creation), so `create_room` never fires for them at all.
- **Untracked flows:** the shopping checklist itself (creation, item add/remove, budget changes), the AI 3D-generation pipeline (Trellis wake → status → generate → import), catalog/gallery engagement (likes/views — written straight to Supabase), and guest-to-account conversion have no dedicated analytics calls. Only the endpoint of the purchase flow (`click_affiliate`) is instrumented.
- **Client vs. server:** entirely client-side. No tracking in the Cloudflare Worker (`worker/`) or any Supabase edge function (`glb-to-usdz`, `request-unfurl-deploy`, `sign-share-assets`).
